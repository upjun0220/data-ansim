# Claude Code 구현 프롬프트 — 「충전 리플맵 4.2」 파이프라인

> 이 프롬프트를 Claude Code(또는 다른 코딩 에이전트) 새 세션에 그대로 붙여넣어 구현을 맡기세요.
> 2026 데이터+AI 혁신 챌린지(데이터안심구역 부문) 제출용 파이프라인 스펙입니다.

## 0. 프로젝트 배경

숭실대 전기공학과 3학년 5인 팀이 참가하는 데이터 경진대회용 파이프라인을 구현합니다. 최종 산출물은
**안심구역 현장(인터넷 차단 PC, JupyterLab + QGIS만 사용 가능)에서 실제 데이터로 실행**할 코드입니다.
지금 이 세션에는 실제 데이터가 없으므로, **모든 로더 함수는 실제 컬럼 스키마와 100% 동일한 구조의
mock/synthetic CSV로 개발·테스트**하고, 로더 함수 자체는 데이터 경로만 바꾸면 실데이터에 바로
돌아가도록 작성해주세요.

**한 줄 컨셉**: 전기차 충전소가 인근 상권 매출에 미치는 효과는 상권마다 다르다. 같은 법정동 내
거주자 소비 대조 + 업종 대조 + 스태거드 이벤트 스터디를 결합한 삼중차분(DDD)으로 충전 활성화의
인과 효과를 추정하고, Causal Forest로 상권 유형별 이질적 효과(CATE)를 뽑아, 전력 부하 축과
결합한 4사분면 처방(충전기 우선 배치 지도)을 만든다. 단정적 인과("낙수효과 있다")가 아니라
조건부 결론("이런 상권에서는 크고, 저런 상권에서는 없다")을 낸다.

## 3. 결합키 처리 — 텍스트 대 코드

`bjd_mapping.py`는 아래 순서로 동작해야 합니다.
1. 법정동코드 마스터 CSV(시도명/시군구명/읍면동명 ↔ 10자리 법정동코드)를 로드.
2. KEPCO의 `시도`+`시군구`+`읍면동` 텍스트를 마스터와 매칭해 법정동코드를 부여.
3. 동명이인 읍면동 방지를 위해 반드시 시도+시군구+읍면동 **3단 전체**로 매칭할 것(읍면동명 단독 매칭 금지).
4. 표기 차이("제1동" vs "1동" 등) 완화를 위한 간단한 정규화 함수(공백 제거, "제"/숫자 통일 등)를 두되,
   자동 정규화로 못 푼 매칭 실패 건은 반드시 별도 리스트로 남겨 사람이 검토하게 할 것.
5. 매칭률표(전체 대비 매칭 성공 비율)와 미매칭 목록을 항상 출력.
6. 이 모듈은 마스터 CSV 경로를 함수 인자로 받는 구조로 작성 — 하드코딩 금지.

## 4. 식별 설계 상세 — `identification.py`

### Y_ddd 축약 (법정동 r, 월 m마다 하나의 값)
```
Y_ddd(r, m) = [ log S(외지, 대기소비업종) − log S(거주자, 대기소비업종) ]
            − [ log S(외지, 대조업종)     − log S(거주자, 대조업종)     ]
```
- 대기소비 가능 업종: 카페·편의점·음식점·소매. 대조(불가능) 업종: 병원·학원·전문서비스.
  `TOBU_BIDVS_CD`/`TOBU_MEDVS_CD` 매핑표는 설정 파일로 분리(하드코딩 금지 — 현장에서 실제 코드값 확인 후 채움).
- 외지/거주자 구분은 `IFW_DISTC_SECT_CD`(유입거리구간) 기준 — 가장 가까운 구간을 "거주자"로 간주하는
  임계값도 설정 파일로 분리.
- `S(...)`가 0이거나 마스킹으로 결측이면 그 (법정동, 월) 셀은 스킵하고 결측 사유를 로그로 남길 것.
  `log(S+1)` 옵션도 함수 인자로 켤 수 있게 해주세요(마스킹으로 인한 결측 폭 완화용, 09절 "여전히
  막지 못하는 것" 참고).

### 스태거드 이벤트 스터디
- 처치: 2단계에서 얻은 T_r (충전 활동 활성화 시점). τ(k) = 활성화 후 k개월 효과, k = −5…+5
  (단, 실제로는 데이터가 짧아 k가 이보다 좁을 수 있음 — 가용 범위를 자동으로 계산해 좁혀서 표시).
- 추정기는 Callaway–Sant'Anna 방식을 우선 시도(패키지가 있으면), 없으면 **음의 가중치 편향이 있는
  2기간 TWFE는 쓰지 말고**, 처치군 내에서 상대시점(k) 기준으로 지역 고정효과 + 시점 고정효과를 넣은
  event-study 회귀로 직접 구현(현장 패키지 없을 때의 확실한 폴백). 표준오차는 법정동 단위 클러스터.
- 사전 기간(k<0) 계수가 유의하게 0이 아니면 해당 지역을 표본에서 제외하거나 "유보" 플래그를 달 것.

### 위약(대조 업종) 검정
- 위 Y_ddd 계산에서 "대기소비업종" 자리에 대조 업종을 넣어 같은 추정기로 τ(k)를 다시 계산.
- 위약 효과가 0이 아니면, 그 크기만큼 주 결과를 할인해서 보고하는 후처리 함수를 반드시 포함
  (숨기지 말 것 — 리포트에 할인 전/후 값을 모두 출력).

### [신규] 처치오염 진단 — `diagnostics.py`
- T_r 전후 몇 개월 동안 SHC001의 가맹점 **개설률**(신규 등록 / 기존 가맹점수)이 함께 급등하는 지역을
  탐지(예: 사전 대비 사후 개설률이 임계치 이상 증가 — 임계치는 설정 가능하게).
- 급등이 감지된 지역은 "상권 자체 성장일 가능성 — 유보" 플래그를 달아 CATE·최종 처방 리포트에서
  별도로 표기(제외하지는 않되, 시각적으로 구분).

## 5. CAN 처치 정제 — `can_loader.py` (반드시 분기 로직으로 구현)

CAN M-Type의 `차종_식별번호`가 개별 차량 단위인지 차종 모델 코드인지 현장 검증 전까지 불명입니다.
아래 두 경로를 모두 구현하고 검증 결과에 따라 자동 분기하도록 작성해주세요.

**검증 함수** `verify_join_key(can_df) -> "individual" | "model" | "unknown"`:
1. `차종_식별번호`의 distinct 값 개수와 레코드 수 비율을 확인 — distinct 값당 평균 레코드 수가
   한 차량의 관측 기간에 합리적인 수준이면 개별 차량 후보.
2. 같은 `차종_식별번호`로 그룹화 후 시간순 정렬해 배터리상태_SOC 등 시계열이 한 차량의 궤적으로
   그럴듯한지(예: 급격한 비정상 점프가 드문지) 점검.
3. 판정 근거(distinct 값 개수, 이상치 비율 등)를 로그로 남기고 `"individual"`/`"model"`/`"unknown"` 반환.

**경로 A — 개별 차량 단위로 확정된 경우:**
- `충전중여부`(CHARGERCONNECTION) 전이로 충전 세션(시작~종료) 재구성 → 세션 길이 분포 산출
  (03절 "20~40분 체류" 전제를 데이터로 검증하는 리포트).
- 차량별 충전 시작 위치(GPS)를 클러스터링(DBSCAN, `eps` 파라미터화)해 "자주 반복되는 위치"
  (거점성 충전: 자가·직장)와 "비반복 위치"(공용 충전)를 구분.
- 거점성 충전이 다수인 법정동은 2단계에서 탐지한 변화점의 신뢰도를 낮추는 플래그로 남기고,
  "거점성 제외" 버전의 처치 지역 목록도 별도로 산출(파이프라인 3단계 산출물).

**경로 B — 모델 코드로 확정되었거나 판정 불가한 경우:**
- 개별 차량 클러스터링은 시도하지 않음(잘못된 결론으로 이어지므로).
- 차종 구분 없이 전체 충전 이벤트 GPS를 모아 **법정동 단위 충전 위치 밀집도**만 집계.
- 세션 길이 분포(03절 실증)는 개별 차량 식별 없이도 계산 가능하므로 이건 경로 A/B 공통으로 항상 산출.
- 리포트에는 "개별 차량 ground-truth"라는 표현을 쓰지 말고 "정황상 보조 근거" 수준으로만 표기.

**격리 설계 원칙**: `can_loader.py` 전체가 예외를 던지거나 실패해도 0·1·2·4·5·6·7·8단계는 영향받지
않고 정상 실행되도록 try/except로 감싸고, 실패 시 "CAN 처리 생략됨" 로그와 함께 3단계 리포트 섹션만
비워두는 구조로 작성해주세요.

## 6. 이질성 변수 + Causal Forest — `heterogeneity.py`

**Bad Control 방지**: SHC 기반 이질성 변수(업종 구성비, 가맹점 밀도·개폐업률, 기존 외지 유입 비중,
고객 구성)는 **반드시 2025년 1~2월(모든 지역의 최초 활성화 후보 2025.03 이전) 고정 스냅샷**으로만
계산할 것. 연간 평균이나 처치 이후 월을 포함해 계산하지 말 것 — 이게 이 모듈의 핵심 제약입니다.

| 변수 | 출처 | 시점 |
|---|---|---|
| 업종 구성비 | SHC002 | 2025.01~02 고정 |
| 가맹점 밀도·개폐업률 | SHC001 | 2025.01~02 고정 |
| 기존 외지 유입 비중 | SHC002 유입거리 | 2025.01~02 고정 |
| 고객 구성 | SHC002 | 2025.01~02 고정 |
| 세션 특성(평균 체류시간, 거점성 비율) | CAN | 2022.11~ (분석기간 이전이라 오염 없음) |
| 인프라 스톡(급속·완속 대수) | KEP_007 | 정적 스냅샷 |

**절대 넣지 말 것**: "충전 집중도(피크 시간대 점유율)" — 07절 전력 축(세로축)과 같은 개념이라
CATE 피처에 넣으면 두 축이 모델 구조상 상관관계를 갖게 됩니다. 부하 관련 정보는 `load_axis.py`
에서만 사용.

**Causal Forest**: EconML(`econml.dml.CausalForestDML` 등) 또는 R `grf`가 있으면 사용해 CATE와
변수 중요도를 산출. **없으면** 사전지정 서브그룹(업종구성 상/하위 × 외지유입 상/하위 2×2)으로
자동 폴백하는 `estimate_cate_fallback()` 함수를 반드시 구현. 어느 경로든 결과를 같은 평가셋으로
비교하는 검증 리포트를 출력할 것(06절 원칙: "단순 서브그룹 대비 실제로 더 나은지 검증").

## 7. 전력 축 + 4사분면 — `load_axis.py`

```python
집중도(r) = max_h Load(r, h) / sum_h Load(r, h)   # h: 시간대구간
```
- 시간값이 1시간 구간 에너지(kWh)라면 `kWh / 1h`가 그 구간의 **평균 kW**임을 코드 주석에 명시
  (순간 최대전력 아님 — 리포트에도 이 구분을 반드시 남길 것).
- 4사분면: (CATE 추정치, 부하 집중도) 두 축으로 ①증설 최우선 ②증설+시간대 분산 유도 ③상권 연계
  프로그램 우선 ④신규 투자 최후순위로 분류하는 함수.
- `load_axis.py`는 KEPCO_001/002만 입력으로 받고 06절 CATE 피처와는 완전히 독립적으로 동작해야
  합니다(6절의 "충전 집중도 제외" 규칙을 코드로 강제).

## 8. 킬 크라이테리아 자동 체크 — `kill_criteria.py`

첫 방문 반나절(목표 30분) 안에 아래 8개를 한 번에 판정하는 스크립트. 각 항목은 통과/실패와 근거
숫자를 함께 출력해야 합니다.

1. 패키지 확인: `ruptures`, `econml`, `linearmodels`, `statsmodels`, `sklearn` import 시도.
2. 2025.03~09 활성화 후보 지역 수(전후 3개월 평균 비율 방식, **중복 집계 금지 — set으로 고유
   법정동만 카운트**) — 30곳 미만이면 Causal Forest 포기 경고, 10곳 미만이면 이벤트 스터디 포기 경고.
3. `TIZO_CLCD` 구간 수 — 4개 미만이면 시간대 축 포기 경고.
4. `IFW_DISTC_SECT_CD` 구간 정의 확인 — 값이 1개뿐이면 층1 불가 경고.
5. 한전 "읍면동" 매핑 실패율 — `bjd_mapping.py` 결과 재사용, 실패율 30% 이상이면 "행정동 기준일
   가능성" 경고.
6. 마스킹 비율 — SHC002 집계 후 결측/마스킹 비율 30% 초과 시 PK 축소(성별·연령·소득 제거) 권고.
7. KEPCO_001/002 포함관계 — 표본 일부에서 002 ⊆ 001 여부를 카운트 기반으로 점검, 불명확하면 합산
   금지 경고.
8. CAN `verify_join_key` 결과 출력 — "individual"/"model"/"unknown" 및 판정 근거.

## 9. 산출물/반출 규칙 (매우 중요) — `outputs.py`

안심구역에서 반출 가능한 산출물은 **①이미지 캡처(PNG) ②output 없는 코드**뿐이고, 수치가 그대로
든 CSV 표 파일은 반출 대상이 아닐 가능성이 높습니다. 모든 표·통계 결과를 **두 가지 형태로 동시에
생성**해주세요.
1. CSV — 현장 작업용(반출 대상 아님)
2. PNG — 같은 표/차트를 이미지로 렌더링(matplotlib table 또는 seaborn/plotly static export) — 실제 반출용

**GPS 규칙**: CAN 기반 산출물(경로 A·B 모두)은 개별 차량 좌표나 원본 GPS 포인트를 최종 이미지에
절대 노출하지 말 것. 항상 법정동 단위로 집계된 통계·히트맵·클러스터 요약 형태로만 시각화.
